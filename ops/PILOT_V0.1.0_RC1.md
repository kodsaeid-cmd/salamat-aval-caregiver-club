# برنامه پایلوت کنترل‌شده باشگاه مراقبین سلامت اول

نسخه: `v0.1.0-rc.1`

## هدف

اعتبارسنجی مسیر واقعی استفاده از باشگاه بدون انتقال انبوه CRM و بدون ایجاد ریسک برای ارزیابی‌ها، کارنامه‌ها و پرونده‌های مراقبین.

## دامنه پایلوت

- حداقل ۲۰ و حداکثر ۵۰ مراقب واقعی
- ۵ کاربر ستادی: مدیر اصلی، مدیر محدود، کارشناس جذب، ارزیاب و منابع انسانی/پشتیبان
- مدت مشاهده اولیه: حداقل ۷ روز کاری
- ورود انبوه ۴۰ هزار مراقب در این مرحله ممنوع است

## معیار انتخاب مراقبین

ترکیب پایلوت باید شامل موارد زیر باشد:

- مراقب جدید و مراقب باسابقه
- مراقب دارای ارزیابی قبلی و بدون ارزیابی قبلی
- مراقب با سطح حرفه‌ای متفاوت
- کاربران موبایل Android و iOS
- حداقل پنج کاربر دسکتاپ
- حداقل پنج پرونده دارای آموزش، قرارداد یا سابقه پشتیبانی

## مسیرهای اجباری آزمون

1. ورود و خروج و بازیابی نشست
2. مشاهده داشبورد متناسب با نقش
3. ورود به پرونده مراقبین و دریافت فهرست از سرور
4. بازکردن کارنامه مراقب از همان کلیک اول
5. ایجاد دوره ارزیابی
6. ثبت و اصلاح امتیاز و مشاهده Revision
7. نهایی‌سازی و ایجاد Snapshot غیرقابل‌تغییر
8. مشاهده کارنامه توسط مراقب
9. مشاهده آموزش‌های تخصیص‌یافته
10. ثبت پیام یا درخواست پشتیبانی
11. خروج از ماژول پرونده مراقبین بدون قفل‌شدن ناوبری
12. تست موبایل و دسکتاپ برای همه مسیرهای اصلی

## کنترل روزانه داده

هر روز پیش از شروع کار:

- بررسی `GET /api/admin/evaluation-protection/health`
- کنترل `finalWithoutSnapshot = 0`
- کنترل `scoresWithoutRevision = 0`
- کنترل `orphanScores = 0`
- کنترل خالی‌بودن `snapshotHashes.mismatches`
- بررسی موفقیت آخرین D1 Backup
- ثبت هر خطای Worker با زمان، نقش و مسیر

## شرایط توقف فوری پایلوت

- گم‌شدن یا تغییر ناخواسته یک ارزیابی نهایی
- عدم ایجاد Snapshot هنگام نهایی‌سازی
- ناسازگاری Hash کارنامه
- نمایش اطلاعات مراقب دیگر به کاربر
- دورزدن سطح دسترسی
- نیاز به کلیک یا Refresh تکراری برای دریافت داده سرور
- شکست بک‌آپ روزانه برای دو اجرای متوالی
- شکست Restore Drill

## معیار عبور به نسخه نهایی v0.1.0

- حداقل هفت روز استفاده بدون باگ مسدودکننده
- تکمیل حداقل ۲۰ مسیر ارزیابی واقعی
- موفقیت صددرصدی Snapshot و Revision
- موفقیت بک‌آپ روزانه
- حداقل یک Restore Drill موفق پس از شروع پایلوت
- تأیید مدیر اصلی، مسئول ارزیابی و مسئول جذب
- بسته‌شدن تمام خطاهای شدت بحرانی و بالا

## داده‌های لازم برای آغاز پایلوت

فهرست شرکت‌کنندگان باید خارج از Repository و در فایل امن سازمانی نگهداری شود و فقط شامل شناسه‌های لازم برای Import باشد. اطلاعات هویتی، رمزها و شماره‌های تماس نباید در GitHub Issue یا فایل Markdown ثبت شوند.

## تصمیم انتشار

تا زمان عبور کامل از معیارهای بالا، نسخه `v0.1.0-rc.1` یک Release Candidate است و انتقال کامل CRM یا اعلام نسخه نهایی مجاز نیست.
